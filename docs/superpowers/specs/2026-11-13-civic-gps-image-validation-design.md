# Civic reporting: GPS and evidence validation

The existing Next.js civic report form accepts 1–3 photos, optional GPS or manual coordinates, and a written address. Reports and photos are stored in MySQL through Prisma and shown to authorized desk staff. Extend this flow without duplicating reporting.

Citizens should see an automatic GPS attempt on opening the form, an address lookup, the estimated accuracy, and a map they can correct. Permission failure leaves manual coordinates and address available. Coordinates are submitted as citizen supplied data, never independently certified. An authenticated server route resolves coordinates to an address with bounded requests; the citizen can edit it. Capture timestamp and source are saved.

Every submitted photo is re-encoded and inspected on the server against the chosen category and report title/description using OpenAI vision. The model must return structured visible observations, a category relevance decision, a score, and a brief reason. A configured API key is required for submission; failures and uncertain results fail closed. The server does not trust a browser validation token. Validated results belong to each persisted photo. An optional preview endpoint gives per-photo feedback before submission; changing the category invalidates the preview. Revalidate on final submission to prevent bypass or swapped files. Ambiguous categories such as OTHER may require staff review, but the image must still visibly support the described concern.

The admin desk shows saved report pins with status/category/location filters, and authorized staff can open report details including the same coordinates, address, evidence and AI results. The existing role/office scope applies. OpenStreetMap tiles and optional Geoapify reverse geocoding are external services; HTTPS is required for browser GPS outside localhost. AI predictions are fallible and do not establish the incident's truth. Per-user hourly limits bound provider use. No live API key or database is available in this workspace, so tests cover request/response policy with controlled fixtures and type/build checks; live integration requires a configured environment.
